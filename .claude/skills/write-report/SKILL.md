# TDL Trend 리포트 작성

기사 선정과 기획 의도는 웹에서 저장되고, 글쓰기는 여기(Claude Code)에서 한다.
`ANTHROPIC_API_KEY` 를 요구하거나 SDK 로 API 를 호출하지 않는다.
생성 규칙(문체, 구성, 사실 처리, 분량)은 `src/config/report-rules.ts` 에 사전 정의되어 있고 의뢰서의 [작성 지침]에 그대로 들어간다. 규칙을 바꾸려면 그 파일을 고친다.

## 0. 저장 위치

- 내 PC 모드(기본): 의뢰서가 `data/handoff/<호수>/` 파일로 있다.
- 웹 모드(`STORE_MODE=sheets`): 구글 시트 `Handoffs` 탭에 있다. `GOOGLE_SHEETS_SPREADSHEET_ID`, `GOOGLE_SERVICE_ACCOUNT_KEY_JSON` 이 환경에 있어야 한다. 없으면 환경 설정에서 넣어 달라고 안내한다(채팅에 키를 붙여 넣게 하지 않는다).

## 1. 의뢰서 확인

```bash
npm run report -- list
```

- 호수 인자가 있으면 그 호를, 없으면 `작성 대기` 중 가장 최근 호를 고른다.
- 의뢰서가 없으면 사용자에게 선택지를 준다.
  - 웹 대시보드에서 기사를 고르고 **📝 작성 의뢰 저장**
  - 여기서 같이 고르기: `npm run report -- candidates 14` 로 후보와 지난 호 연관 태그를 보여 주고, 기사 4~8건·기획 의도·발행일을 정한 뒤
    `npm run report -- request <호수> --date YYYY-MM-DD --concept "..." --articles ID,ID,...`
  - 기사가 비어 있으면 `npm run collect -- 14` 로 먼저 수집한다(네트워크 필요).

## 2. 의뢰서 읽기

```bash
npm run report -- prompt <호수>
```

`data/handoff/<호수>/prompt.md` 를 처음부터 끝까지 읽는다. 작성 지침, 선정 기사 원문, **서버가 계산한 통계**, 지난 호 이력, 출력 JSON 스키마가 들어 있다.

## 3. 작성

`data/handoff/<호수>/content.json` 에 JSON 하나만 쓴다(코드블록 표시 없이).

- 기사를 건별로 요약하지 않는다. 공통 주제로 **묶어서** 테마 2~4개를 만들고, 테마마다 기사 형태(제목·리드·본문·인사이트·시사점)로 쓴다.
- 선정된 기사는 모두 어느 테마의 `sourceArticleIds` 에 인용한다(제공된 articleId 만 사용). 인용된 기사는 리포트에서 [번호] 원문 링크가 된다.
- 숫자는 기사 본문과 제공된 통계에서만 가져온다. `trend` 는 통계에 있는 호별 추이만 인용한다.
- 통계·차트·참고 기사 목록은 서버가 만들므로 JSON 에 넣지 않는다.
- 작업자의 기획 의도를 리포트 전체의 관점으로 반영한다.
- **하이라이트:** `keyTakeaway`(이번 호 한 줄 결론)와 테마마다 `takeaway`(핵심 한 줄)를 쓴다. 핵심 요약·핵심 인사이트 문장마다 가장 중요한 구절 하나를 `**두 별표**`로 감싼다(형광펜 표시가 된다). 본문은 문단당 최대 1곳. 많이 감싸면 아무것도 눈에 띄지 않는다.

## 4. 저장·검증

```bash
npm run report -- save <호수>
```

- 형식 오류는 필드 경로와 함께 출력된다. 고쳐서 다시 저장한다.
- `⚠ 어느 테마에도 인용되지 않은 선정 기사`가 나오면 해당 기사를 테마에 추가하고 다시 저장한다.
- 통과하면 근거 기사 ID 가 정리되고 통계가 붙어 저장된다.

## 5. 스스로 점검

content.json 을 다시 읽고 확인한다. 고칠 게 있으면 고쳐서 다시 save.

- 합니다체이고 이모지·구어체·과장 표현이 없는가
- 핵심 요약이 결론 먼저, 각 1문장인가
- 한 줄 결론과 주제별 핵심 한 줄이 있고, 하이라이트가 문장당 1곳 이하인가
- 시사점이 CL사업부 센터 운영 관점에서 구체적인가
- 기사에 없는 수치나 사실이 없는가
- 제안이 검토·확인할 대상이 분명한가

## 6. 보고

사용자에게 짧게 알린다: 제목, 테마별 한 줄 요약, 인용되지 않은 기사 유무.
“웹 대시보드 › 리포트 작성 현황 › **작성본 불러오기**로 화면에서 확인(리포트 보기)하고 **📋 메일 본문용 복사**를 눌러 아웃룩에 붙여 넣으세요. 확정하려면 **✅ 발행 확정**.”
여기서 발행까지 원하면 `npm run report -- publish <호수>`. git commit·push 는 사용자가 요청할 때만 한다.
